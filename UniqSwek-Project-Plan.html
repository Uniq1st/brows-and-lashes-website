🎓 Your TPM Learning Path

A Technical Program Manager (TPM) bridges business goals and technical execution. You are already doing TPM work on this project — managing a website build, coordinating between tools (Square, GA4, Formspree, Behold), tracking priorities, and driving revenue outcomes. This section makes that learning intentional and transferable to any company or role.

What a TPM does

  • Defines scope, timeline, and success metrics
  • Breaks big goals into trackable tasks
  • Manages dependencies (task B can't start until task A is done)
  • Communicates status to stakeholders
  • Identifies and mitigates risks before they become problems
  • Bridges technical teams and business owners

How this project teaches it

  • You are the project owner managing Claude as a technical resource
  • Prioritizing tasks = TPM scope management
  • The promo system = TPM release planning
  • GA4 + Square reports = TPM metrics tracking
  • Git commits + Vercel deploys = TPM release management
  • Formspree → Mailchimp integration = TPM systems thinking

Frameworks you're using

  • MoSCoW prioritization (Must/Should/Could/Won't)
  • Phased delivery (Phase 1/2/3/4)
  • OKRs (Objective: grow revenue / KRs: 50 members, $16K/mo)
  • Risk log (what breaks if you don't fix the bridal form?)
  • Dependency mapping (Square URLs needed before memberships go live)
  • Retrospective (quarterly sanity check)

Tools to learn next

  • Notion or Linear — for structured project tracking
  • Figma — to understand design specs and handoffs
  • GitHub — you're already using it; learn branching strategy
  • JIRA or Asana — used by tech companies for sprint planning
  • SQL basics — to query your own Square/GA4 data
  • Google Project Management Certificate (free on Coursera)
Write a project brief before starting any new feature
Before asking Claude to build something, write 2–3 sentences: what problem does this solve, who is the user, what does success look like? This is the single most important TPM habit.
Applied in: Every new website feature request
Track your KPIs in a monthly dashboard
TPMs live and die by metrics. Build a simple monthly tracker (spreadsheet is fine): revenue, active members, email subscribers, GA4 booking clicks, avg ticket. Review it every month and ask "why did this go up or down?"
Applied in: Monthly Square + GA4 review
Write a post-mortem when something goes wrong
When the Mother's Day promo was missed, a TPM would write: "What happened, why, what we'll do differently." Practice this — it's the most valued skill in tech. Blameless, factual, and forward-looking.
Applied in: Missed Mother's Day promo, git lock incidents
Learn git branching: create a staging branch for experiments
Right now all changes go directly to main and deploy to live. A TPM understands release management: create a "staging" branch for experiments, only merge to main when tested. Protects the live site from broken features.
Applied in: Website development workflow
Complete Google Project Management Certificate (Coursera)
Free with financial aid. 6 months, ~10 hours/week. Covers Agile, Scrum, Kanban, stakeholder management, risk registers, and project charters. This credential opens doors to TPM roles at any tech company.
Resource: coursera.org/professional-certificates/google-project-management
Read "The Art of Project Management" by Scott Berkun
Written by a former Microsoft PM. Covers how to actually run projects in the real world — not just theory. Practical frameworks for scope, decisions, and communication. One of the most-read books in the field.
Resource: Available on Amazon, ~$20
Document your technical decisions with ADRs (Architecture Decision Records)
Any time you make a significant tech choice (using Square over Stripe, Formspree over a custom backend, Behold for Instagram), write a 1-paragraph ADR: what decision, why this option, what alternatives were considered. TPMs are the institutional memory of a project.
Applied in: Square API choice, GA4 implementation, Vercel deployment
Build a risk register for the business
A risk register lists what could go wrong and what you'll do about it. For UniqSwek: "Square API goes down → fallback to static prices." "A stylist leaves → cross-train on all services." "Website breaks → Vercel rollback steps." TPMs prevent fires; they don't just fight them.
Applied in: All phases of this project
